============================================================
1. 제품 개요
============================================================

1-1. 서비스 한 줄 정의

현생 RPG는 사용자가 하루를 짧게 기록하면, 그 기록을 게임 패치노트와 캐릭터 성장 시스템처럼 보여주는 자기기록 웹앱이다.

1-2. 핵심 컨셉

기존 일기 앱은 사용자가 직접 긴 글을 써야 해서 진입장벽이 높다. 현생 RPG는 수면, 식사, 소비, 감정처럼 짧게 입력할 수 있는 생활 데이터를 기반으로 하루 상태를 자동 계산하고, 이를 게임식 문구와 스탯 변화로 보여준다.

또한 사용자마다 안정적인 하루의 기준이 다르다는 점을 반영해, 온보딩 과정에서 사용자의 100점 기준을 설정할 수 있도록 한다. 예를 들어 어떤 사용자는 6시간 수면으로도 충분하지만, 다른 사용자는 8시간 이상 자야 컨디션이 좋을 수 있다. 식사 횟수, 카페인 과부하 기준, 소비 경고 기준도 사용자별로 다를 수 있다.

따라서 현생 RPG는 모든 사용자를 동일한 기준으로 평가하지 않고, 사용자가 설정한 현생 밸런스 기준을 기반으로 하루를 판정한다.

사용자는 매일 자신의 하루를 다음과 같은 방식으로 확인할 수 있다.

예시:

오늘의 현생 패치노트

상태: 수면부족 / 커피버프 / 통장출혈

체력 -15
집중력 -20
지갑 -35

오늘의 판정:
“이번 하루도 어찌저찌 클리어했습니다.”

1-3. 제품 목표

이 프로젝트의 목표는 단순한 기록 앱이 아니라, 사용자가 자신의 하루를 가볍고 재미있게 돌아볼 수 있는 경험을 만드는 것이다.

MVP 단계에서는 다음 흐름을 완성하는 것을 최우선 목표로 한다.

캐릭터 생성 → 현생 밸런스 설정 → 오늘 기록 입력 → 능력치 계산 → 패치노트 카드 생성 → 날짜별 저장 → 최근 기록 확인 → 캐릭터 성장 확인

2. 문제 정의
============================================================

2-1. 사용자 문제

사용자는 자신의 하루를 기록하고 싶어도 다음과 같은 이유로 꾸준히 기록하지 못한다.

- 긴 글을 쓰는 일기는 부담스럽다.
- 매일 같은 형식의 기록은 금방 지루해진다.
- 기록을 해도 재미있는 피드백이 부족하다.
- 기록이 쌓였을 때 나의 변화를 직관적으로 보기 어렵다.
- 기존 자기관리 앱은 모든 사용자에게 비슷한 기준을 적용하는 경우가 많아 개인의 생활 패턴을 충분히 반영하기 어렵다.
- 수면, 식사, 카페인, 소비 기준은 사람마다 다르기 때문에 고정된 기준으로 점수를 매기면 사용자가 결과를 부정확하게 느낄 수 있다.

2-2. 해결 방향

현생 RPG는 기록을 “해야 하는 일”이 아니라 “오늘의 결과 화면을 확인하는 일”로 바꾼다.

이를 위해 다음 방식을 사용한다.

- 긴 글 대신 선택형 입력 중심으로 구성한다.
- 온보딩에서 사용자의 현생 밸런스 기준을 설정할 수 있게 한다.
- 입력값을 사용자의 기준에 맞춰 스탯, 상태 태그, 판정 메시지로 자동 변환한다.
- 날짜별 기록을 누적해 사용자의 생활 패턴을 보여준다.
- 캐릭터 시트와 스킬 시스템을 통해 성장감을 제공한다.
- 기본값을 제공해 설정 부담을 줄이고, 설정 화면에서 언제든 수정 가능하게 한다.

============================================================
3. 타겟 사용자
============================================================

3-1. 주요 사용자

- 20~30대 직장인, 취준생, 대학생
- 일기는 부담스럽지만 하루 기록에는 관심이 있는 사용자
- 게임, 밈, 패치노트, 레벨업 같은 표현에 친숙한 사용자
- 자기관리 앱을 딱딱하게 느끼는 사용자
- 본인의 생활 기준에 맞는 가벼운 자기기록 서비스를 원하는 사용자

3-2. 사용자 니즈

| 니즈 | 설명 |
|---|---|
| 빠른 기록 | 하루 기록을 1분 이내에 끝내고 싶다. |
| 재미있는 피드백 | 단순 저장이 아니라 결과를 보고 싶다. |
| 누적 확인 | 내가 요즘 어떤 상태인지 보고 싶다. |
| 부담 없는 자기관리 | 생산성 앱처럼 무겁지 않았으면 좋겠다. |
| 개인 기준 반영 | 내 생활 패턴에 맞는 기준으로 하루를 판정받고 싶다. |

============================================================
4. MVP 범위
============================================================

4-1. MVP 핵심 목표

MVP에서는 다음 다섯 가지 기능을 완성한다.

1. 캐릭터 생성 및 현생 밸런스 설정
2. 오늘의 기록 입력
3. 패치노트 결과 카드 생성
4. 날짜별 기록 저장
5. 최근 7일 기준 캐릭터 요약 표시

4-2. MVP에 포함하는 기능

| 기능 | 포함 여부 | 설명 |
|---|---|---|
| 온보딩 / 캐릭터 설정 | 포함 | 캐릭터명, 클래스 설정 |
| 현생 밸런스 설정 | 포함 | 수면, 식사, 카페인, 소비 기준 설정 |
| 오늘 기록 입력 | 포함 | 수면, 식사, 카페, 소비, 감정, 메모 입력 |
| 능력치 계산 | 포함 | 입력값과 사용자 기준 기반 체력, 집중력, 지갑 등 계산 |
| 상태 태그 생성 | 포함 | 수면부족, 커피버프, 통장출혈 등 자동 생성 |
| 패치노트 카드 | 포함 | 하루 결과를 게임 UI처럼 표시 |
| localStorage 저장 | 포함 | 로그인 없이 브라우저에 기록 저장 |
| 기록 리스트 | 포함 | 날짜별 기록 확인 |
| 캐릭터 미니 시트 | 포함 | 최근 7일 평균 스탯 표시 |
| 특수스킬 3종 | 포함 | 카페인 의존, 돼지력, 거지되기 |
| 설정 화면 | 포함 | 캐릭터 정보, 현생 밸런스 수정, 데이터 초기화 |
| 캘린더 뷰 | 선택 | 시간이 남으면 구현, 아니면 Phase 2 이후 |
| 외부 API 연동 | 제외 | 날씨, 미세먼지, 공휴일은 Phase 3 이후 |
| 로그인 | 제외 | MVP에서는 사용하지 않음 |
| 서버 DB | 제외 | MVP에서는 사용하지 않음 |
| AI 분석 | 제외 | MVP에서는 사용하지 않음 |

4-3. MVP 제외 범위

다음 기능은 MVP에서 제외한다.

- 회원가입 / 로그인
- Supabase 또는 서버 DB 저장
- OpenWeatherMap 날씨 API 연동
- 에어코리아 미세먼지 API 연동
- 공공데이터포털 공휴일 API 연동
- 카드 이미지 저장 / 공유
- AI 기반 분석 메시지
- 복잡한 월간 리포트
- 푸시 알림
- 모든 스탯별 가중치 커스텀
- 판정 메시지 직접 커스텀
- 태그 조건 전체 커스텀
- 복잡한 점수 계산 공식 커스텀

5. 핵심 사용자 시나리오
============================================================

5-1. 첫 방문 사용자

1. 사용자가 앱에 접속한다.
2. 캐릭터 정보가 없으므로 온보딩 화면으로 이동한다.
3. 캐릭터 이름과 클래스를 설정한다.
4. 현생 밸런스 설정 화면으로 이동한다.
5. 사용자는 수면 100점 기준, 식사 100점 기준, 카페인 과부하 기준, 소비 경고 기준을 설정한다.
6. 설정이 귀찮은 경우 기본값으로 시작할 수 있다.
7. 설정이 완료되면 홈으로 이동한다.
8. 오늘 기록이 없으므로 오늘의 패치노트 작성 버튼이 표시된다.
9. 사용자가 작성 버튼을 누른다.
10. 수면, 식사, 카페, 소비, 감정을 입력한다.
11. 저장 버튼을 누른다.
12. 사용자 기준을 기반으로 스탯, 태그, 판정 메시지가 계산된다.
13. 오늘의 패치노트 카드가 생성된다.
14. 사용자는 자신의 하루 상태와 스탯 변화를 확인한다.

5-2. 재방문 사용자

1. 사용자가 앱에 접속한다.
2. 저장된 캐릭터 정보와 현생 밸런스 설정을 불러온다.
3. 홈에서 최근 7일 평균 스탯을 확인한다.
4. 오늘 기록이 없으면 작성 버튼이 표시된다.
5. 오늘 기록이 있으면 오늘의 패치노트 카드 요약이 표시된다.
6. 사용자는 기록 탭에서 과거 기록을 확인할 수 있다.
7. 사용자는 캐릭터 탭에서 최근 7일 평균 스탯과 특수스킬 진행도를 확인할 수 있다.

5-3. 기록 수정 사용자

1. 사용자가 기록 리스트에서 특정 날짜를 선택한다.
2. 해당 날짜의 패치노트 상세 화면을 본다.
3. 수정 버튼을 누른다.
4. 입력값을 변경한다.
5. 저장하면 현재 현생 밸런스 설정을 기준으로 스탯, 태그, 스킬 상태가 다시 계산된다.
6. 수정된 결과 카드가 표시된다.

5-4. 현생 밸런스 수정 사용자

1. 사용자가 설정 화면으로 이동한다.
2. 현생 밸런스 설정 영역을 선택한다.
3. 수면 100점 기준, 식사 100점 기준, 카페인 과부하 기준, 소비 경고 기준을 수정한다.
4. 저장하면 이후 새로 작성하거나 수정하는 기록에 변경된 기준이 반영된다.
5. MVP에서는 기존 기록의 계산 결과를 자동 일괄 재계산하지 않는다.
6. 단, 추후 Phase에서 기존 기록 재계산 옵션을 제공할 수 있다.

7. 기능 요구사항
============================================================

7-1. 온보딩 / 캐릭터 설정

목적

사용자가 자신의 캐릭터 정보를 설정한다.

입력 항목

| 항목 | 타입 | 필수 여부 | 기본값 |
|---|---|---|---|
| 캐릭터명 | text | 필수 | 없음 |
| 클래스명 | select 또는 text | 필수 | 취준생 |

클래스 기본 옵션

- 취준생
- 직장인
- 대학생
- 프리랜서
- 백수
- 직접 입력

요구사항

- 첫 방문 시 캐릭터 정보가 없으면 온보딩 화면을 보여준다.
- 캐릭터 정보를 저장하면 현생 밸런스 설정 화면으로 이동한다.
- 캐릭터 정보는 localStorage에 저장한다.
- 설정 화면에서 캐릭터 정보를 수정할 수 있다.

7-2. 현생 밸런스 설정

목적

사용자마다 안정적인 하루의 기준이 다르기 때문에, 수면 시간, 식사 횟수, 카페인 과부하 기준, 소비 경고 기준을 사용자가 직접 설정할 수 있도록 한다.

이 설정값은 이후 스탯 계산, 상태 태그 생성, 판정 메시지 생성에 사용된다.

기능 명칭

기능명은 “현생 밸런스 설정”으로 한다.

보조 문구 예시:

사람마다 안정적인 하루의 기준은 달라요.
내 캐릭터에게 맞는 기준을 정해두면,
패치노트가 더 정확하게 계산됩니다.

입력 항목

| 항목 | 타입 | 필수 여부 | 기본값 | 설명 |
|---|---|---|---|---|
| 수면 100점 기준 | number 또는 slider | 필수 | 7시간 | 사용자가 컨디션이 좋다고 느끼는 수면 시간 |
| 식사 100점 기준 | segmented button | 필수 | 3회 | 사용자가 안정적이라고 느끼는 하루 식사 횟수 |
| 카페인 과부하 기준 | stepper | 필수 | 4회 이상 | 이 횟수 이상이면 카페인 과부하로 판단 |
| 소비 경고 기준 | number 또는 quick select | 필수 | 50,000원 | 이 금액 이상이면 통장출혈로 판단 |

요구사항

- 첫 온보딩 과정에서 캐릭터 생성 후 현생 밸런스 설정 화면을 제공한다.
- 사용자는 기본값으로 바로 시작할 수 있다.
- 사용자가 값을 변경하면 해당 값을 localStorage에 저장한다.
- 설정값이 없을 경우 기본값을 사용한다.
- 설정 화면에서 언제든 현생 밸런스 값을 수정할 수 있다.
- 현생 밸런스 설정값은 스탯 계산, 상태 태그 생성, 판정 메시지 생성에 반영된다.
- 기준값은 개인화하되, 계산 공식 자체는 앱이 관리한다.
- MVP에서는 기존 기록을 자동으로 전체 재계산하지 않는다.
- 기록을 수정할 경우 수정 시점의 현생 밸런스 설정으로 다시 계산한다.

기본값

const DEFAULT_BALANCE_SETTINGS = {
  idealSleepHours: 7,
  idealMealCount: 3,
  caffeineOverloadCount: 4,
  spendingWarningAmount: 50000,
};

버튼

- 기본값으로 시작하기
- 설정 완료

7-3. 오늘의 패치노트 작성

목적

사용자가 오늘의 생활 데이터를 빠르게 입력한다.

입력 항목

| 항목 | 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| 날짜 | 자동 | 필수 | 기본값은 오늘 날짜 |
| 수면 시간 | slider 또는 number | 필수 | 0~12시간 |
| 식사 횟수 | segmented button | 필수 | 0~4회 |
| 카페 횟수 | stepper | 필수 | 0회 이상 |
| 배달/간식 횟수 | stepper | 필수 | 0회 이상 |
| 소비 금액 | number 또는 quick select | 필수 | 0원 이상 |
| 오늘의 감정 | emoji select | 필수 | 1개 선택 |
| 한 줄 메모 | textarea | 선택 | 최대 100자 |

감정 옵션

| 값 | 라벨 | 내부 값 |
|---|---|---|
| 😊 | 평온 | calm |
| 😵 | 피곤 | tired |
| 😡 | 분노 | angry |
| 😭 | 멘탈붕괴 | sad |
| 😎 | 자신감 | confident |
| 🫠 | 녹아내림 | melted |

요구사항

- 사용자는 오늘 날짜의 기록을 작성할 수 있다.
- 이미 오늘 기록이 있으면 새로 작성이 아니라 수정 화면으로 진입한다.
- 필수값이 비어 있으면 저장할 수 없다.
- 저장 시 현생 밸런스 설정을 함께 참조해 스탯, 상태 태그, 판정 메시지, 스킬 진행도를 계산한다.
- 저장 후 패치노트 결과 카드 화면으로 이동한다.
- 저장 버튼 문구는 “저장하기”보다 “패치노트 생성하기”를 우선 고려한다.

7-4. 능력치 계산

목적

사용자의 입력값과 현생 밸런스 설정값을 기반으로 게임식 스탯을 계산한다.

기본 스탯

| 스탯 | 설명 |
|---|---|
| 체력 | 수면, 식사 상태의 영향을 받음 |
| 집중력 | 수면, 카페 횟수, 감정의 영향을 받음 |
| 사회성 | 감정과 외부 활동 추정값의 영향을 받음 |
| 지갑 | 소비 금액의 영향을 받음 |
| 외출의지 | 감정, 수면, 소비 패턴의 영향을 받음 |

계산 원칙

- 각 스탯은 0~100 범위의 숫자로 계산한다.
- 기본값은 100에서 시작한다.
- 조건에 따라 점수를 더하거나 뺀다.
- 최종 결과는 0 미만이면 0, 100 초과면 100으로 보정한다.
- 수면, 식사, 카페인 과부하, 소비 경고는 사용자의 현생 밸런스 설정을 참조한다.
- 계산 공식 자체는 MVP에서 사용자가 직접 커스텀하지 않는다.

보정 함수

function clampStat(value: number) {
  return Math.max(0, Math.min(100, value));
}

수면 계산 예시

function getSleepModifier(sleepHours: number, idealSleepHours: number) {
  if (sleepHours >= idealSleepHours) return 10;
  if (sleepHours <= idealSleepHours - 2) return -30;
  return -15;
}

예시:

- idealSleepHours = 7, sleepHours = 5
- idealSleepHours - 2 = 5
- sleepHours가 5 이하이므로 -30

식사 계산 예시

function getMealModifier(mealCount: number, idealMealCount: number) {
  if (mealCount >= idealMealCount) return 5;
  if (mealCount <= idealMealCount - 2) return -15;
  return -5;
}

예시:

- idealMealCount = 3, mealCount = 1
- idealMealCount - 2 = 1
- mealCount가 1 이하이므로 -15

체력 계산 예시

기본값: 100

- 수면 modifier 반영
- 식사 modifier 반영

예시:
- idealSleepHours = 7
- sleepHours = 5
- idealMealCount = 3
- mealCount = 2

계산:
- 수면 modifier = -30
- 식사 modifier = -5
- 체력 = 100 - 30 - 5 = 65

집중력 계산 예시

기본값: 100

- 수면 시간이 기준보다 2시간 이상 부족하면 -25
- 수면 시간이 기준보다 부족하면 -10
- 카페 1~2회: +5
- 카페 횟수가 caffeineOverloadCount 이상이면 -15
- 감정이 tired 또는 melted이면 -15

지갑 계산 예시

기본값: 100

- 소비 0원: +10
- 소비 금액이 spendingWarningAmount 이상이면 -40
- 소비 금액이 spendingWarningAmount의 60% 이상이면 -25
- 소비 금액이 spendingWarningAmount의 20% 이상이면 -10

예시:
- spendingWarningAmount = 50000
- spending = 30000
- 50000의 60% = 30000
- 지갑 -25

사회성 계산 예시

기본값: 100

- 감정이 calm 또는 confident이면 +5
- 감정이 angry 또는 sad이면 -20
- 수면 시간이 기준보다 2시간 이상 부족하면 -10

외출의지 계산 예시

기본값: 100

- 수면 시간이 기준보다 2시간 이상 부족하면 -20
- 감정이 melted 또는 tired이면 -20
- 소비 0원: -5
- 카페 횟수 1회 이상: +5

7-5. 상태 태그 생성

목적

스탯 계산 결과와 입력값, 현생 밸런스 설정값을 바탕으로 오늘의 상태를 짧은 태그로 보여준다.

상태 태그 규칙

| 태그 | 조건 |
|---|---|
| 수면부족 | 수면 시간이 idealSleepHours보다 1시간 이상 부족 |
| 꿀잠 | 수면 시간이 idealSleepHours 이상 |
| 커피버프 | 카페 횟수 1회 이상 |
| 카페인 과부하 | 카페 횟수가 caffeineOverloadCount 이상 |
| 통장출혈 | 소비 금액이 spendingWarningAmount 이상 |
| 절약성공 | 소비 금액 0원 |
| 멘탈위기 | 감정이 sad 또는 melted |
| 분노상태 | 감정이 angry |
| 정상작동 | 위험 태그가 없는 경우 |

태그 우선순위

화면에서 태그를 최대 3개만 보여줄 경우 다음 우선순위를 따른다.

1. 카페인 과부하
2. 통장출혈
3. 멘탈위기
4. 수면부족
5. 분노상태
6. 커피버프
7. 꿀잠
8. 절약성공
9. 정상작동

요구사항

- 하나의 기록에 여러 태그가 붙을 수 있다.
- 태그가 하나도 없으면 정상작동 태그를 붙인다.
- 태그는 패치노트 카드, 기록 리스트, 상세 화면에 표시한다.
- 현생 밸런스 설정값을 참조해 수면부족, 꿀잠, 카페인 과부하, 통장출혈 태그를 판단한다.

7-6. 패치노트 결과 카드

목적

오늘 기록의 결과를 게임 패치노트처럼 보여준다.

표시 정보

- 날짜
- 요일
- 캐릭터명
- 클래스명
- 상태 태그
- 스탯 변화 또는 스탯 점수
- 오늘의 판정 메시지
- 한 줄 메모

카드 예시

오늘의 현생 패치노트

버전: v2026.05.15 금요일
캐릭터: 수지 / 클래스: 취준생

상태:
수면부족 / 커피버프 / 통장출혈

능력치:
체력 55/100
집중력 60/100
사회성 80/100
지갑 35/100
외출의지 45/100

오늘의 판정:
이번 하루도 어찌저찌 클리어했습니다.

판정 메시지 규칙

| 조건 | 메시지 예시 |
|---|---|
| 체력 30 이하 | 침대와의 재협상이 필요합니다. |
| 지갑 30 이하 | 통장이 조용히 울고 있습니다. |
| 평균 스탯 40 미만 | 긴급 점검이 필요한 하루입니다. |
| 평균 스탯 40 이상 | 살짝 위험했지만 하루를 넘겼습니다. |
| 평균 스탯 60 이상 | 무난하게 생존에 성공했습니다. |
| 평균 스탯 80 이상 | 오늘은 꽤 안정적인 하루였습니다. |

판정 메시지 우선순위

1. 체력 30 이하
2. 지갑 30 이하
3. 평균 40 미만
4. 평균 60 미만
5. 평균 80 미만
6. 평균 80 이상

예시 코드

function generateJudgementMessage(stats: DailyStats) {
  const average = getAverageStat(stats);

  if (stats.hp <= 30) return '침대와의 재협상이 필요합니다.';
  if (stats.wallet <= 30) return '통장이 조용히 울고 있습니다.';
  if (average < 40) return '긴급 점검이 필요한 하루입니다.';
  if (average < 60) return '살짝 위험했지만 하루를 넘겼습니다.';
  if (average < 80) return '무난하게 생존에 성공했습니다.';
  return '오늘은 꽤 안정적인 하루였습니다.';
}

요구사항

- 저장 후 자동으로 카드가 생성되어야 한다.
- 카드에는 사용자가 입력한 메모가 선택적으로 표시된다.
- 모바일 화면에서 카드가 한 화면에 잘 보이도록 구성한다.
- 카드 화면은 MVP의 핵심 재미 요소이므로 가장 높은 우선순위로 완성도를 높인다.
- 결과 카드에는 최종 점수를 표시하고, 상세 화면에서는 점수 산정 이유를 일부 보여줄 수 있다.

7-7. 기록 리스트

목적

사용자가 과거 기록을 날짜별로 확인한다.

표시 정보

- 날짜
- 요일
- 대표 감정 이모지
- 상태 태그 최대 3개
- 평균 스탯

요구사항

- 최신 날짜순으로 정렬한다.
- 기록이 없으면 빈 상태 UI를 보여준다.
- 기록 카드를 클릭하면 상세 화면으로 이동한다.
- 상세 화면에서 수정 또는 삭제할 수 있다.

7-8. 캐릭터 미니 시트

목적

사용자의 최근 상태를 캐릭터 시트처럼 보여준다.

표시 정보

- 캐릭터명
- 클래스명
- 레벨
- 최근 7일 평균 스탯
- 대표 상태 메시지

레벨 규칙

MVP에서는 레벨을 나이와 분리한다. 사용자가 나이를 입력하지 않아도 사용할 수 있도록 한다.

추천 MVP 규칙:

- 1~2일 기록: Lv.1
- 3~6일 기록: Lv.2
- 7~13일 기록: Lv.3
- 14~29일 기록: Lv.4
- 30일 이상 기록: Lv.5

추후 Phase에서 생년월일 기반 레벨 또는 나이 기반 레벨을 선택 옵션으로 제공한다.

최근 7일 평균 계산

1. 최근 7일 기록을 가져온다.
2. 각 스탯의 합계를 구한다.
3. 합계 / 기록 개수로 평균을 계산한다.
4. 기록이 없으면 기본값 0 또는 안내 문구를 보여준다.

요구사항

- 홈 화면에서 캐릭터 미니 시트를 보여준다.
- 기록이 없으면 “첫 패치노트를 작성해보세요” 메시지를 보여준다.
- 최근 7일 평균 스탯은 기록이 저장, 수정, 삭제될 때마다 다시 계산한다.
- 대표 상태 메시지는 최근 7일 평균에서 가장 낮은 스탯을 기준으로 생성할 수 있다.

대표 상태 메시지 예시

- 체력이 가장 낮음: 요즘은 회복 루틴이 필요한 상태입니다.
- 지갑이 가장 낮음: 지갑 방어막이 약해진 상태입니다.
- 집중력이 가장 낮음: 집중력 서버가 불안정합니다.
- 외출의지가 가장 낮음: 외출 퀘스트 수락률이 낮아진 상태입니다.

7-9. 특수스킬 시스템 MVP

목적

사용자의 누적 행동을 스킬 성장처럼 보여준다.

MVP 스킬 목록

| 스킬 | 조건 | 설명 |
|---|---|---|
| 카페인 의존 | 카페 2회 이상인 날 누적 | 커피로 하루를 버티는 능력 |
| 돼지력 | 배달/간식 횟수 1회 이상인 날 누적 | 먹는 것에서 행복을 찾는 능력 |
| 거지되기 | 소비 0원인 날 누적 | 지갑 방어에 성공하는 능력 |

레벨 계산 규칙

MVP에서는 모든 스킬의 만렙을 Lv.5로 설정한다.

- 0회: Lv.0
- 1~2회: Lv.1
- 3~5회: Lv.2
- 6~9회: Lv.3
- 10~14회: Lv.4
- 15회 이상: Lv.5

요구사항

- 스킬 레벨은 저장된 DailyLog 데이터를 기반으로 계산한다.
- 스킬 레벨은 직접 저장하지 않는다.
- 기록이 수정되거나 삭제되면 스킬 레벨도 자동으로 다시 계산된다.
- 만렙 달성 시 MAX 배지를 표시한다.
- 카페인 의존 스킬의 기준은 MVP에서는 “카페 2회 이상”으로 고정한다.
- 추후 Phase에서 카페인 의존 스킬 기준도 사용자 설정과 연동할 수 있다.

- 사용자가 현생 밸런스 기준을 설정하거나 기본값으로 시작할 수 있다.

17. 면접 / 포트폴리오 설명 포인트
============================================================

17-1. 프로젝트 의도

현생 RPG는 일기를 꾸준히 쓰기 어려운 문제를 게임식 피드백으로 해결하려는 프로젝트다. 사용자가 긴 글을 쓰지 않아도, 짧은 입력만으로 하루의 상태를 패치노트처럼 확인할 수 있도록 설계했다.

또한 사람마다 좋은 하루의 기준이 다르다는 점을 반영해, 온보딩에서 사용자의 현생 밸런스 기준을 설정할 수 있도록 했다. 이를 통해 단순히 고정된 기준으로 점수를 매기는 것이 아니라, 사용자 개인의 생활 패턴에 맞는 결과를 제공하는 방향으로 설계했다.

17-2. 기술적으로 보여줄 수 있는 점

- React 기반 컴포넌트 설계
- TypeScript를 활용한 데이터 모델링
- Zustand 기반 클라이언트 상태관리
- localStorage persist 구조
- 날짜별 데이터 관리
- 입력값 기반 파생 데이터 계산
- 사용자 설정값을 반영한 계산 로직
- 조건 분기 기반 스탯 / 태그 / 스킬 로직
- 원본 데이터와 파생 데이터 분리
- 모바일 우선 반응형 UI

17-3. 차별점

단순 CRUD 기록 앱이 아니라, 사용자의 입력값을 게임식 결과로 변환하는 비즈니스 로직이 핵심이다. 또한 캐릭터 시트, 스킬, 태그, 판정 메시지를 통해 사용자가 자신의 데이터를 재미있게 해석할 수 있도록 만든다.

특히 현생 밸런스 설정을 통해 사용자마다 다른 생활 기준을 반영할 수 있다. 수면, 식사, 카페인, 소비 기준을 개인화하면서도 계산 공식은 앱이 관리하도록 하여, 개인화와 사용 편의성 사이의 균형을 맞춘다.

17-4. 면접 답변 예시

이 프로젝트는 단순한 일기 CRUD가 아니라, 사용자의 생활 입력값을 기반으로 스탯, 상태 태그, 판정 메시지, 스킬 레벨 같은 파생 데이터를 계산하는 구조로 설계했습니다.

특히 사람마다 안정적인 수면 시간이나 식사 횟수, 카페인 과부하 기준이 다르다고 생각해 온보딩에서 현생 밸런스 기준을 설정할 수 있도록 했습니다.

사용자가 직접 입력한 원본 데이터는 DailyLog로 저장하고, 최근 평균이나 스킬 레벨은 저장하지 않고 계산하도록 설계했습니다. 이렇게 하면 기록 수정이나 삭제가 발생해도 데이터 불일치를 줄일 수 있습니다.

18. 미정 사항
============================================================

다음 항목은 MVP 개발 중 추가 결정이 필요하다.

- 캘린더 뷰를 MVP에 포함할지 여부
- 캐릭터 레벨을 기록 횟수 기준으로 할지 나이 기준으로 할지 여부
- 소비 금액 기준을 사용자가 직접 커스텀할 수 있게 할지 여부
- 스킬 이름과 문구의 톤을 어느 정도까지 유머러스하게 가져갈지 여부
- 추후 서버 저장 기능을 Supabase로 확장할지 여부
- 현생 밸런스 수정 시 기존 기록을 재계산할지 여부
- 카페인 의존 스킬 기준도 사용자 설정과 연동할지 여부
- 수면 100점 기준 외에 최소 수면 기준을 별도로 받을지 여부
- 지갑 점수를 소비 경고 기준 하나만으로 계산할지, 단계별 기준을 추가할지 여부

19. MVP 최종 요약
============================================================

현생 RPG MVP의 핵심은 다음 한 문장으로 정리된다.

사용자가 자신의 생활 기준을 설정한 뒤, 하루 생활 데이터를 짧게 입력하면, 앱이 이를 게임 패치노트와 캐릭터 스탯으로 변환해 저장하고 보여준다.

따라서 MVP 개발에서는 기능을 많이 넣는 것보다, 다음 핵심 루프의 완성도를 우선한다.

1. 내 기준을 설정하기 쉽다.
2. 하루 기록을 입력하기 쉽다.
3. 결과 카드가 재미있다.
4. 기록이 쌓이면 캐릭터가 변한다.
5. 다시 들어와서 확인하고 싶다.

============================================================
20. 다른 AI에게 전달할 작업 기준
============================================================

이 PRD를 기반으로 개발 작업을 수행할 AI는 다음 원칙을 따른다.

1. MVP에서는 기능 확장보다 핵심 루프 완성을 우선한다.
2. 패치노트 결과 카드의 재미와 가독성을 가장 중요한 UX 요소로 본다.
3. 사용자가 직접 입력한 원본 데이터와 계산 가능한 파생 데이터를 분리한다.
4. 스킬, 최근 평균, 캐릭터 레벨은 저장하지 않고 DailyLog를 기반으로 계산한다.
5. 현생 밸런스 설정값은 스탯 계산과 태그 생성에 반드시 반영한다.
6. 사용자가 설정을 건너뛰어도 DEFAULT_BALANCE_SETTINGS로 앱이 정상 작동해야 한다.
7. 모바일 우선 반응형 UI를 기준으로 구현한다.
8. 자기비하적 표현보다 유쾌한 생존 기록 톤을 유지한다.
9. MVP에서는 로그인, 서버 DB, 외부 API, AI 분석을 구현하지 않는다.
10. localStorage 기반으로 새로고침 후에도 데이터가 유지되어야 한다.
